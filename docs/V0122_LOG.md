# 0.12.2 step log: crash reports + skill details beside the popup

Started 2026-10-15 after Umut's report: a colleague's game "crashed" after a level (black screen, the mini log still
visible, 60 FPS), and since recently the skill details window sits right on top of a ground skull's popup.
Running log (one entry per step, survives a context compaction). Decisions marked [DECISION].

## Findings (before any change)

1. **The crash was not on Umut's PC**: Umut's last Skul session was 2026-10-12; his Player.log has only game errors
   (Witch/Fox/Ogre/DeathKnight.OnDisable, ControlLetterBox, Duel inscription coroutine, UIManager.Update cast),
   none with mod code. The colleague's logs are not available, so nothing says whose fault it was. That is the gap.
2. **What the black screen is**: `Level.Chapter.CChangeMap` (game code) = fade to black → `Chronometer` time scale 0
   and `PlayerInput.blocked` → destroy the old map → `Resources.UnloadUnusedAssets` → load the new map (Addressables)
   → instantiate it, spawn/position the player, camera, background → save → `InvokeOnMapChanged` → fade in → unblock.
   If anything in that coroutine throws (or the map load never finishes), the coroutine dies: the fade stays black,
   time stays stopped, the game keeps rendering at 60 FPS. The game's HUD is under the fade; our overlay canvases
   (mini log) are above it. Exactly picture 2.
3. **Mod code can't throw into game code from hooks**: every Harmony hook runs through `Guard` (tested), our
   subscriptions to events (`onStartAction`, AttackTracker events, settings) are guarded too. The fight camera
   renders only into its own texture. So a mod fault would have to be something subtler; without a log we can't say.
4. **Skill details over the popup**: the game's prefab (dumped with tools/unity/dump_gearpopup.py) puts
   `DetailContainer` at the centre of the popup's container: the skill box (158x169), the two skill boxes (pivots
   right/left of the centre) and the inscription boxes (158x343) are drawn ON the popup by design. New since 0.12:
   the game's details key (Down; on a controller the only way, there is no Shift) also shows the mod's numbers in the
   popup (commit 3e056aa), so the popup grows and the game's box covers exactly those numbers. The QA pictures of
   2026-10-11 show the same (Recruit__popup_detail.png). The inventory's detail view has its own layout: fine.

## Plan

- [DECISION] **Crash reports** (setting General/CrashReports, on): one text file per game session in
  `BepInEx/DamageInsight/CrashReports` (newest 20 kept), written as it happens (survives a hard crash):
  header (mod, game, Unity, OS, Proton/Wine, language, other plugins, changed settings), a timeline (scenes,
  chapter/stage/map changes, fades, run start/end, save slot switch...), every distinct error once with its count and
  stack trace, each classified: MOD (our code in the trace), HOOKED (a game method the mod patches is in the trace),
  OTHER MOD, GAME. A verdict at the end. Detects the **stuck black screen** (fade fully black for 20 s, no loading
  screen, not paused) and writes what happened right before; shows a notice on screen. At the next start a session
  without a clean end is marked "ended unexpectedly" (with Unity's Player-prev.log tail and a Unity crash folder's
  error.log if there is one) and a notice says so.
- [DECISION] **Details beside the popup** (setting Descriptions/DetailsBeside, on): while the details key is held,
  the game's skill / inscription boxes open next to the ground or shop popup (left/right, wherever there is room)
  instead of on top of it; if the screen has no room, the game's own place.
- Version 0.12.2, changelog, README, translations (10 languages), settings rows, tests. Release only on Umut's go.

## Steps

1. **Crash reports built** (DamageInsight/Crash/): `ErrorClassifier` (plain: our namespace in a trace = MOD; a
   `DMD<Type::Method>` frame of a method one of our Harmony ids patches = HOOKED, nested coroutine names handled by
   counting angle brackets; another plugin's namespace or a method only another mod patches = OTHER MOD; else GAME),
   `SessionReport` (plain: file per session, timeline, each distinct error once with its stack, repeats counted,
   incidents with a verdict from the errors since 10 s before the screen went black, summary snapshot
   `<report>.summary.txt` every 2-30 s so a hard crash still has a verdict, `FinishPrevious` at the next start, the
   newest 20 kept), `CrashReporter` (Unity: `Application.logMessageReceivedThreaded`, a BepInEx `ILogListener` for
   error lines of every source, `Guard.Report` -> Caught; polling of scene, chapter/stage/map, player spawn/death,
   build per map, fade, map object (removed / new), game camera; stuck = fade alpha >= 0.99 for 20 s in the game
   scene, no loading screen, no dialogue / narration / letterbox / credits; state dump: map change phases, game time
   scale, `PlayerInput.blocked` holders, player, camera, memory; Wine/Proton detection via ntdll `wine_get_version`;
